# 圈子管理功能前端对接实施计划

## 现状结论（探索所得）

- 项目为 Vue 3 + Naive UI + vue-i18n，**无 TypeScript/Pinia**，API 用 JSDoc 风格；请求封装在 `src/utils/request.js`（响应拦截器已处理 202/401 未登录跳登录、错误以 `error.code`/`error.message` reject，成功返回 `{code,message,data}` 信封）——**无需改动 request.js**。
- 圈子 API 在 `src/api/circle.js`（尚无成员列表/管理/编辑接口）；圈子详情页 `src/views/CircleDetail.vue` 已读取 `member_role/member_status/join_type` 且有 `getRoleInfo/getMemberStatusInfo` 映射（缺 status 3/4）；**无任何管理入口**。
- 页面组装模式：每页自行引入 `AppHeader` + `SideNav` + `.main-content`；路由扁平，权限校验先例是 `/admin/agents`（requiresAuth + 页面内自查角色）。
- 可复用资产：游标分页 + IntersectionObserver（`CircleDetail.vue` sentinelRefMap 模式、`Notifications.vue` loadGen 防竞态）、行内三点 NDropdown（`MyPosts.vue`）、useDialog 危险确认（`AppHeader.vue`）、头像/封面上传链路（`CreateCircleModal.vue` → ImageCropperModal → useImageUpload.uploadOne）、Tab 计数角标（`UserDetail.vue` 的 NTag 用法）、骨架屏 `PostListSkeleton`。
- 样式遵循 frontend-style-constraints：复用 `main.css` token、绿色强调色、scoped 样式只写自己的 DOM，teleport 弹层用默认全局暗色皮肤（本期无需新增全局覆盖）。

## 页面设计

### CircleMembers.vue（成员管理页）
- 进入先 `getCircleDetail`：取圈名/头像做页头 + 权限守卫（`member_role<20` → message 提示并跳回 `/circle/:id`）。
- NTabs 四个 Tab（参照 UserDetail 角标写法）：待审核(status=0，NBadge 角标) / 正常成员(1) / 禁言中(2) / 已拉黑(3)。每 Tab 独立 `members/cursor/hasMore/loading` 状态（仿 tabStateMap），游标分页 + 每页 20 + IntersectionObserver 哨兵 + loadGen 世代号防切 Tab 竞态；首屏骨架屏、翻页底部 NSpin；空态文案。
- **待审核角标**：挂载时拉 `status=0&size=20` 一页，满页显示「20+」，否则显示实际条数；审核操作后重查。
- 成员行：NAvatar（空头像回退首字母，注意 default slot 优先级坑）+ SmartLink 用户名（/user/:id）+ 角色 NTag + 禁言截止剩余时间（`mute_end_time` 本地倒计时文案，过期由后端自动解禁）+ 加入时间（useFormatTime）+ 操作区。
- 行操作（严格按权限矩阵 `canTarget` 显隐，目标 role≥自己一律不渲染）：
  - 待审核 Tab：[通过] [拒绝]（owner+admin 均可）。
  - 正常成员 Tab：对 role<自己 的行内联 [禁言] [拉黑]；圈主额外显示三点 NDropdown：设为管理员(target=10)/免去管理员(target=20)/转让圈主；管理员仅对 role=10 行显示内联按钮。
  - 禁言中 Tab：[解除禁言] [拉黑]。
  - 已拉黑 Tab：[解除拉黑]（弹窗说明对方可重新申请）。
- 弹窗与确认：禁言 → NModal(preset=card) 预设 1h/24h/7天/30天 + NInputNumber 自定义(1-720)；转让圈主 → useDialog 强确认（文案明示不可逆、自己即刻降为普通成员），成功后跳回圈子详情并刷新；拉黑/免去管理员/拒绝申请 → useDialog.warning；通过/解禁/解黑直接执行。
- 错误码统一处理函数 `handleManageError(error)`：**按 error.code 分支渲染自有文案，不展示后端英文 message** — 409→「成员状态已变化」并就地刷新当前 Tab；203→「无权限」并重拉详情，若角色已降级则跳回详情页；204→「成员不存在」并刷新列表；201→表单/参数提示；202 已由拦截器全局跳登录；其余兜底。
- 操作成功（code=200）→ message.success + 就地刷新当前 Tab 第一页 + 重查待审核角标；不依赖 `member_count` 做校验（最终一致）。

### CircleEdit.vue（圈子资料编辑页）
- 同样先拉详情做守卫（`member_role<20` 拒绝），以详情数据初始化表单并保留初始快照。
- 按 §5.9 权限渲染两个分组卡片：圈主专属（name 1-50、slug ≤60 正则校验、join_type NRadioGroup、category_id NSelect 来自 getCategories、clearable→清除时提交全零 UUID）；管理员可改（avatar/cover 走 NUpload+ImageCropperModal+useImageUpload 上传链路（照搬 CreateCircleModal 接线）、可清空；description 必填 1-2000 不可清空；rule ≤2000 可清空传 ""）。
- **只提交变更字段**：computed diff 初始快照，无变更时保存按钮禁用（防后端 400）；提交前本地长度/必填校验（后端 201 仅兜底）。
- 保存成功 → message + 提示详情缓存秒级延迟属预期；409 → name/slug 重名提示改字段；403 → 管理员误改圈主字段时提示并不部分提交。

## 实施顺序

1. `src/constants/circle.js` + `src/composables/useCircleMeta.js` + CircleDetail 小重构（映射抽公共、补 status 3/4 文案）。
2. `src/api/circle.js` 9 个接口封装（JSDoc 注明字段约束与特殊语义，如 slug 传 ""、分类全零 UUID、role/status 字符串传参）。
3. 路由 + CircleDetail moreOptions 入口。
4. `CircleMembers.vue`：页面框架/守卫 → Tab 与游标分页列表 → 行操作与弹窗/确认 → 错误码分支 → 待审核角标。
5. `CircleEdit.vue`：表单分组 → 上传链路 → diff 提交与校验。
6. zh-CN / en-US 文案补全。

## 验证

- `npm run build` 通过（项目无 lint/test 脚本）。
- `npm run dev` 手动走查：圈主/管理员两种角色下的入口显隐、四 Tab 列表与翻页、每类操作的确认弹窗与成功/409/203 分支、编辑页角色分组与 diff 提交、中英文案。
- 对照文档自检清单：不给普通成员暴露入口、不调用 P1 接口（reason/审计/通知）、不展示后端 message、role/status 传字符串、转让后本地圈主状态失效处理。

## 边界与不做的事

- 不接入站内信/操作原因/审计（P1）；不支持普通成员查看成员列表。
- 不新建 Pinia store；转让圈主后以「跳转详情并重拉」方式失效本地角色状态。
- 成员数显示不做严格校验；角标采用「一页探测」策略（20+）。
