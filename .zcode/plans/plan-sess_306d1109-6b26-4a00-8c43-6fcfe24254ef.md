# 找回密码功能对接方案

采用**模态框**形式，新建 `ForgotPasswordModal.vue` 组件，从 `LoginCard.vue` 的「忘记密码？」链接触发。复用注册流程的三步骤结构与样式。

## 改动清单

### 1. `src/api/auth.js` — 新增三个接口
新增找回密码三步接口（路径 `/auth/password/*`，与注册接口 `/auth/register/*` 平行）：
- `sendPasswordResetCode(email, lang)` → POST `/auth/password/send-code`
- `verifyPasswordResetCode(email, code)` → POST `/auth/password/verify`
- `resetPassword(email, newPassword)` → POST `/auth/password/reset`（注意字段名 `new_password`，snake_case）

### 2. `src/utils/request.js` — 扩展 `isAuthRequest` 白名单
当前只放行 `/auth/login`、`/auth/register`，找回密码三端点返回的 401/403 会被拦截器误判为「会话过期」而跳转。在 `isAuthRequest` 中补充 `/auth/password`，让这些公开端点的错误正常交由调用方处理。

### 3. `src/components/ForgotPasswordModal.vue` — 新建组件
镜像 `LoginCard.vue` 注册流程的实现（步骤指示器 + Transition + 同样的 naive-ui 组件与样式类）：

- **Props**: `show`（v-model 控制显隐）
- **Emits**: `update:show`、`success`（携带 email，用于回填登录框）
- **Step 1 邮箱 + 发码**: 邮箱输入 + 「发送验证码」按钮（60s 倒计时）；错误处理：404 邮箱未注册、429 频率限制、400 格式错误、500 服务异常
- **Step 2 验证码**: 6 位验证码输入 + 重发按钮；错误处理：400 expired/invalid
- **Step 3 重置密码**: 新密码 + 确认密码 + 密码强度条（复用注册的强度计算逻辑）；前端校验长度 ≥6；错误处理：403 账号禁用、400 验证过期等
- **成功后**: 提示「密码重置成功，请重新登录」→ emit `success(email)` → 关闭弹窗
- **关闭/重开时**: 重置 step 到 1、清空表单、清掉倒计时定时器

### 4. `src/components/LoginCard.vue` — 接入模态框
- 模板：将 `LoginCard.vue:61` 的 `<span class="forgot-link disabled">` 改为可点击链接（去掉 `disabled` 类，加 `@click` 打开模态框）
- 模板末尾（NTabs 外、`NDivider` 前或 NCard 内末尾）加 `<ForgotPasswordModal v-model:show="forgotModalShow" @success="handleForgotSuccess" />`
- Script: import 组件；新增 `forgotModalShow` ref；`handleForgotSuccess(email)` 把 email 回填到 `loginData.email` 并切换到登录 Tab

### 5. `src/locales/zh-CN.js` & `src/locales/en-US.js` — 新增翻译
在 `login.register` 平级新增 `login.forgotPassword` 命名空间（复用部分通用键，新增找回密码专属键）：
- 标题、各步骤标签、按钮文案、占位符
- 错误提示：邮箱未注册（404）、账号已禁用（403）、验证已过期、密码长度不足、重置成功提示等

## 关键细节（来自文档）
- 找回密码三端点**无需 satoken**，公开访问
- 第 3 步字段名是 `new_password`（snake_case），不是 `password`
- 密码后端只校验 ≥6 位，前端可叠加强度提示但不阻断（这里前端最低门槛保持 ≥6）
- 重置成功**不自动登录**，旧 token 全失效 → 引导用户用新密码登录，邮箱回填到登录框
- `lang` 取当前 UI 语言（复用 `getLangParam()` 逻辑）
- HTTP 状态码不判断业务结果，统一读响应体 `code`（现有 `request.js` 拦截器已按此设计）
