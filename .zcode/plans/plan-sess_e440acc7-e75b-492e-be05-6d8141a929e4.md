# Discover 页列表项多余下划线：根因分析与修复计划

## 根因分析

**1. 直接原因：commit 2ce8479 引入的 `SmartLink` 渲染的是"裸" `<a>` 标签，而项目没有任何全局锚点样式重置。**

- `src/components/SmartLink.vue` 是全站统一跳转组件，模板渲染真实的 `<a :href>`（或降级 `div`），该文件**完全没有 `<style>` 块**。
- 全局样式 `src/assets/main.css` 的 `*` 重置（约 31–36 行）只重置 margin/padding/box-sizing/font-family，**没有任何 `a` 选择器**；项目也未用 Tailwind/UnoCSS 等带 preflight 的框架。因此浏览器 UA 默认的 `a:link { text-decoration: underline }` 全量生效，并沿 inline 文本向下传播到 SmartLink 包裹的所有文字。

**2. 为什么"只有标题没下划线"：**

- 各卡片标题/摘要普遍使用 `display: -webkit-box` + `-webkit-line-clamp` 做行数截断（如 `DiscoverPostTile.vue:110-113` 的 `.tile-title`、`DiscoverCircleCard.vue:121-124` 的 `.desc`），Blink/WebKit 不会把传播的下划线画进 `-webkit-box` 容器 —— 标题因此"幸免"，与 bug 现象完全吻合。
- `PostCard.vue` 的标题 `.post-title` 本来就在链接外（卡片根是 NCard div），只有头部圈名/用户名/时间在 SmartLink 里，所以同样表现为"标题无下划线、其他文字有"。

**3. 为什么漏掉 Discover 页：** 2ce8479 把点击事件替换成 SmartLink 时，作者在 7 个组件里手工补了 `text-decoration: none`（TrendingCard.vue:141、CircleList.vue:222、UserList.vue:223、Notifications.vue:392、AppHeader、SideNav、CommentList、PostHeaderAndContent），但**逐组件打补丁的方式漏掉了以下 8 个**——Discover 页全部中招，还波及共享组件所在的 Home/个人页：

| 缺重置的组件 | Discover 上的表现 |
|---|---|
| `DiscoverCircleCard.vue`（根 SmartLink `.discover-circle-card`，89 行） | mini/card 两种形态的圈名、简介、统计、加入按钮全有下划线 |
| `DiscoverPostTile.vue`（根 SmartLink `.discover-post-tile`，63 行） | 灵感墙方块的 meta、统计有下划线 |
| `RecentPostCard.vue`（根 SmartLink `.recent-post-card`，109 行） | 右侧栏"最近帖子"的圈名、meta 有下划线 |
| `PostCard.vue`（内部 `.circle-info`/`.user-info`/`.author-info`/`.post-cover-link` 四个 SmartLink） | 帖子流卡片的圈名、用户名、时间有下划线 |
| `MyGroups` / `MyFavorites` / `MyPosts` / `BrowseHistory` | 同类隐患（个人页） |

## 修复方案：在 SmartLink 内统一重置（推荐，一处修复全部）

逐组件打补丁已证明会持续遗漏（这次就是 8 处漏网）。SmartLink 本身定位就是"全站统一跳转链接"，链接默认外观理应收敛在组件自身：

**改动文件：仅 `src/components/SmartLink.vue`**，在文件末尾新增：

```vue
<style scoped>
/* SmartLink 是卡片式整块跳转而非文本链接：重置 UA 默认的 a 下划线，
   避免每个使用处重复补 text-decoration:none；确需下划线的场景在使用处自行覆盖 */
a {
  text-decoration: none;
}
</style>
```

scoped 编译后为 `a[data-v-xxx]`，只命中 SmartLink 自己的根 `<a>`，不影响站内其他原生 `<a>`（正文 `.post-mention` 提及链接有 main.css 里的独立显式规则，不受影响）。

**明确不做的事：**
- 不改那 7 个已补 `text-decoration: none` 的组件 —— 它们的显式规则与本次修复同值，保留无害，保持 diff 最小。
- 不动 `main.css`、不加全局 `a { }` 重置 —— 全局重置影响面不可控（可能误伤未来依赖下划线的普通文本链接），收益不比 SmartLink 内修复大。

## 验证步骤

1. `npm run dev` 打开 `/discover`，切换 stream / sectioned / wall 三种模式：确认圈子卡（mini+card）、帖子方块、PostCard 头部圈名/用户名/时间、右侧栏最近帖子的下划线全部消失，标题显示不变。
2. 回归检查共享组件所在页面：Home（PostCard/RecentPostCard）、热点页 Hot、通知页、个人页 MyGroups/MyFavorites/MyPosts/BrowseHistory —— 下划线消失且无其他视觉变化。
3. 确认帖子正文里的 @mention 链接（`.post-mention`）下划线行为不变。
4. `npm run build` 确认编译通过。

改动量为 1 个文件约 6 行，无行为/路由逻辑变化。
