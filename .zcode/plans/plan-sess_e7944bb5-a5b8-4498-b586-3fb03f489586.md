## 访客模式重构方案（Guest Mode Refactor Plan）

基于代码勘察，本项目的鉴权/路由/请求层有以下关键事实，决定了重构策略：

- **三层鉴权门**：① `router/index.js` 的 `meta.requiresAuth` + `beforeEach` 守卫；② 多个视图（Home/Hot/UserDetail/SearchResults/UserProfile）的 `onMounted` 内硬编码 `if (!auth.isAuthenticated()) router.push('/')`；③ `request.js` 响应拦截器对**任何非 auth-flow 的 401** 执行 `localStorage.removeItem('quba_token')` + `window.location.href = '/'` 硬跳转。
- **token 直接从 localStorage 读**（`quba_token`），无 Pinia/响应式 store；`isLoggedIn` 各处用 `computed(() => auth.isAuthenticated())` 重新派生。
- **Discover.vue 已是访客落地参考实现**：`<RightSidebar v-if="isLoggedIn" />`，且 `RightSidebar`/`SideNav` 内部已做匿名跳过拉取。
- **Home 三个 tab**：`recommend` / `hot` / `following`（`latest` 已迁至 RightSidebar）。`recommend` 和 `following` 访客会 401，`hot` 访客可读。
- **点赞/收藏/加入按钮直接调 API**，无 `isAuthenticated` 预检 → 访客点击会触发 401 硬跳转。

---

### 重构分 5 个阶段，按依赖顺序实施

#### 阶段 1：请求层（最底层，所有上层依赖它）

**文件**：`src/utils/request.js`

1. **新增「访客可读接口白名单」模块** → 新建 `src/utils/guest-access.js`：
   - 导出 `GUEST_ACCESSIBLE`（按文档 §2.1/§2.2 的 15 个接口 + 方法）。
   - 导出 `isGuestAccessible(method, url)`：规范化 `method` + 提取 URL pathname（去掉 query），按前缀匹配（如 `/circle/detail/xxx` 匹配 `/circle/detail`）。
   - 对 `/post/home` 特判：仅当 `tab=hot|latest` 时可读，`recommend|following` 视为需登录。
   - 导出 `isFeedTabRestricted(message)`：判断 message === `'This feed tab requires login'`。

2. **改造 401 响应拦截器**（`request.js` 两处 401 处理：业务码 401 在 line 66-70，HTTP 401 在 line 88-91）：
   - 新增分支：若 `isFeedTabRestricted(message)` → **不清 token、不重定向**，直接 reject 交调用方处理。
   - 其余非 auth-flow 的 401 → 保持原行为（清 token + 跳 `/`）。

> ⚠️ **不动请求拦截器的「无 token 阻断」逻辑**——项目本来就没有这个逻辑（请求直接发出，由后端裁决），符合文档 §1.2 的「静默放行」语义。无需新增白名单请求门。

#### 阶段 2：路由层（放开访客可见路由）

**文件**：`src/router/index.js`

移除以下路由的 `meta: { requiresAuth: true }`（改为不加 meta，即公开）：
- `/home`、`/hot`、`/user/:id`、`/search`、`/circle/:id`、`/post/:id`

**保留 `requiresAuth`**：`/create-post`、`/profile`、`/success`（success 本就无 meta，确认）。

#### 阶段 3：视图层「删除/放宽 onMounted 硬门」

逐个文件处理（5 个文件有硬编码 `onMounted` 登录检查）：

- **`src/views/Home.vue`**（line 217-225）：
  - 删除强制跳登录逻辑。
  - 改为：访客态把 `activeTab` 默认值从 `'recommend'` 改为 `'hot'`；`recommend`/`following` tab 在访客态置灰 + 提示「登录后查看」（点击触发登录引导）。
  - 保留 `<RightSidebar v-if="isLoggedIn" />` 模式（参考 Discover）。
- **`src/views/Hot.vue`**（line 155-161）：删除硬门，直接拉 `/trending`（访客可读）。
- **`src/views/UserDetail.vue`**（line 256-262）：删除硬门；访客可看公开主页（API 已开放）。
- **`src/views/SearchResults.vue`**（line 122-129）：删除硬门；搜索接口访客可读。
- **`src/views/UserProfile.vue`**（line ~818）：**保留**——这是「我的资料」，本就需登录。

> CircleDetail.vue 和 PostDetail.vue 只有路由 meta、无 onMounted 硬门，阶段 2 已放开。

#### 阶段 4：登录引导机制（替代硬跳转）

**核心思路**：访客点击需登录的操作时，**不再让请求触发 401 硬跳转**，而是前置拦截 + 弹登录引导。

1. **新建 `src/components/LoginPromptModal.vue`**：一个轻量 `NModal`，复用 `LoginCard` 视觉风格（深色玻璃拟态），含「去登录」「去注册」按钮，可选展示 OAuth 入口。接受 `v-model:show`。登录成功后 emit `success` 并关闭。

2. **新增全局可调用入口**（避免到处 import）：在 `src/utils/auth.js` 增加一个响应式的 `guestActionBus`（用 Vue 的 `ref` + `provide`/`inject` 或最简单的 mitt-like 事件），暴露 `requireLogin(action)` —— 在 App.vue 挂一个全局 `<LoginPromptModal>` 监听它。
   - **简化方案（推荐）**：不做全局 bus，改用「就地拦截」——在每个写操作组件里，点击 handler 先 `if (!auth.isAuthenticated()) { openLoginPrompt(); return }`。登录引导 modal 通过组件级 `v-model:show` 控制。

3. **改造写操作按钮（前置登录检查，避免 401）**：
   - `PostDetail.vue`：`handleLike`/`handleCollect` 加 `auth.isAuthenticated()` 预检。
   - `CommentList.vue`：`handleToggleLike` 加预检。
   - `CircleDetail.vue`：`handleJoinCircle`/`handleLeaveCircle` 加预检。
   - `CircleInfoCard.vue`：`handleJoinCircle`/`handleLeaveCircle` 加预检。
   - `CommentEditor.vue`：访客态隐藏/置灰输入框，提示「登录后评论」。

#### 阶段 5：登录卡片新增「访客入口」

**文件**：`src/components/LoginCard.vue`

在 OAuth 区块**上方**（`NDivider` 与 `oauth-section` 之间，约 line 278）新增一个「以访客身份浏览」入口：
- 一个次级按钮（非主渐变，用玻璃描边风格，符合 §frontend-style-constraints）。
- 文案 i18n：`login.browseAsGuest`（新增到 `zh-CN.js` / `en-US.js`，如「先逛逛 →」/「Browse as guest →」）。
- 点击行为：`router.push('/discover')`（**复用现有访客落地页**，而不是 `/home`——因为 Home 的 `recommend` tab 访客不可用，Discover 是已验证的访客落地参考）。
- 同时调整登录/注册成功后的 `router.push('/home')`（LoginCard line 531、606）：改为**优先返回来源页**（读 `localStorage.getItem('quba_redirect_after_login')` 或 `router.currentRoute.value.query.redirect`），无来源才 fallback 到 `/home`。

**AppHeader 联动**：`src/components/AppHeader.vue` 已支持访客态（line 83-85 显示 Login 按钮 + 路由到 `/discover`）。确认无需改动，或仅在标题点击的 fallback 目标上保持一致。

### 不做的事（明确边界）

- ❌ 不为访客单独写一套 API 调用（文档 §1.2 明确要求复用）。
- ❌ 不处理浏览历史/`view_count` 不计数（文档 §2.2 说明是后端有意行为）。
- ❌ 不改 `latest` tab（已迁至 RightSidebar，本轮不涉及）。
- ❌ 不新建 Category 页面（项目无此页，文档的 `/category/get` 仅用于既有数据）。
- ❌ 不改请求拦截器的 token 注入逻辑（已正确：有 token 才加头，访客不带）。
